# Screw forms and the Properties scrolling axis

The old default V2 ridge could extend a triangular half-profile approximately 0.75 mm past its supporting core. Tests explicitly expected that overshoot, so boundedness tests did not catch the visibly unsupported end. Cup points replaced the end of the thread with a full-major-diameter cylindrical band. Headless cross recesses also depended on a former head diameter hidden by the UI. The old checks established closed bounds and positive volume, rather than connected, meaningful fastener forms.

All new screw generations now use shared original geometry, including the generic legacy-direction Screw. The shaft/thread is clipped to its actual point envelope; gimlet thread roots taper with the supporting core. Chamfered threads continue onto their lead-in. Plain cone, dog and rounded points intentionally retain a smooth nose; choose Threaded gimlet point for a thread extending onto the pointed taper. Cup points cut a recess into a fully threaded end. Generic Thread is bounded at both core ends. Previews also bound the ridge.

Cylindrical and external hex heads have small modelled edge bevels; pan and countersunk heads retain their distinct profiles. Headless recess dimensions use the shaft, independent of a hidden former head diameter. Oversized new recesses are rejected during generation. Validation of stored recipes is unchanged, so older authored meshes remain loadable. Exact axis transforms avoid zero-thickness, detached surfaces at the head/shaft plane. These are generic editable forms, not certified ISO/DIN manufacturing profiles or fit tolerances.

The Properties head/drive controls update their labels and hide irrelevant dimensions immediately, while retaining unapplied edits. Apply is still a transaction and Undo restores the prior geometry. Existing saved meshes are not silently regenerated. To update an existing screw, select it and use Apply shape parameters; retain/Undo the old design as needed.

Properties now scrolls vertically, bounds intrinsic control widths and wraps field labels. Horizontal finger swipes cannot pan the pane. A trusted Chromium touch protocol test at tablet width verifies an actual horizontal swipe keeps scrollLeft at zero, followed by a vertical swipe that increases scrollTop. iPad WebKit checks overflow for every head/point form separately. This is browser gesture verification, not a physical iPad installation test.

Collision preparation retains the source construction's convex thread pieces through intersection with the point envelope. The ordinary source hash, 2% volume and 0.2 mm bounds gates are unchanged. Replacing that construction with whole-mesh decomposition exceeded the compound-piece budget; it was rejected rather than accepted as a solid cylinder. Point/recess Jolt checks run against the actual final geometry.

Tests include all five heads × seven points, connected boundaries, nominal ends, nose cross-sections, fully threaded cup/flat ends, open cup cavities, both hands/two starts, generic Screw/Thread, hidden-head invariance and older saved-recipe loading. Browser checks exercise changing head/drive controls before Apply, exact Undo, all 35 rendered forms, and tablet scrolling. Verification counts and the installed signed build are recorded in the release receipt after completion.
